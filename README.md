# 1. SQL Injection — PortSwigger Web Security Academy

## Introduction

SQL Injection (SQLi) is a web application vulnerability that occurs when an application incorporates untrusted user input into SQL queries without proper validation or parameterization.

An attacker may exploit this vulnerability to manipulate database queries, bypass authentication, or retrieve information from a database.

As part of my practical learning, I completed three SQL Injection labs on PortSwigger Web Security Academy.

## 1.1 Lab: SQL Injection — WHERE Clause Filter Bypass

**Objective:**  
Exploit a SQL Injection vulnerability in a product category filter to display products that are not normally visible.

**Payload Used:**

```sql
Gifts'--
```

**Methodology:**

1. Opened the vulnerable lab on PortSwigger Web Security Academy.
2. Selected a product category and observed the filtering behavior.
3. Examined the request generated by the application.
4. Modified the category parameter by inserting the SQL Injection payload.
5. Used the SQL comment sequence (`--`) to ignore the remaining part of the SQL query.
6. Observed that the application displayed products beyond the selected category.

**Result:**

Successfully bypassed the category filter and solved the lab.

**Key Learning:**

Understood how SQL comment sequences can change query behavior and how vulnerable input parameters can be manipulated.

---

## 1.2 Lab: SQL Injection — Authentication Bypass

**Objective:**  
Exploit a SQL Injection vulnerability in the login functionality to log in as the administrator without knowing the password.

**Payload Used:**

```sql
administrator'--
```

**Methodology:**

1. Opened the login page of the vulnerable application.
2. Identified the username and password input fields.
3. Entered the SQL Injection payload in the username field.
4. Submitted the login request.
5. Observed how the SQL comment sequence caused the remaining part of the query, including the password condition, to be ignored.

**Result:**

Successfully bypassed the login mechanism and accessed the administrator account in the lab environment.

**Key Learning:**

Learned how SQL Injection can affect authentication mechanisms and how improperly handled input can lead to unauthorized access.

## 1.3 Lab: SQL Injection — Determining the Number of Columns Using UNION

**Objective:**  
Determine the number of columns returned by a SQL query and identify which columns can display text.

**Payloads Used:**

First, tested the number of columns using `ORDER BY`:

```sql
ORDER BY 1--
ORDER BY 2--
ORDER BY 3--
ORDER BY 4--
```

Then used:

```sql
UNION SELECT 'a','b','c'--
```

**Methodology:**

1. Opened the vulnerable product category page.
2. Modified the category parameter to test SQL Injection.
3. Used `ORDER BY` statements to identify the number of columns.
4. Observed that queries up to `ORDER BY 3--` worked, while `ORDER BY 4--` produced an error.
5. Concluded that the original query returned three columns.
6. Used a `UNION SELECT` statement with three text values to identify columns capable of displaying text.

**Result:**

Successfully identified three columns and determined which columns could display text. The lab was solved.

**Key Learning:**

- Understood how `ORDER BY` helps determine the number of columns.
- Learned how `UNION SELECT` combines results from multiple queries.
- Understood the importance of matching column counts and compatible data types.

# 2. Network Reconnaissance — Metasploitable 2

## Introduction

Network reconnaissance is the process of gathering information about a target system, including its IP address, open ports, running services, and possible vulnerabilities.

For this practical exercise, I used Nmap and Searchsploit against Metasploitable 2, an intentionally vulnerable virtual machine.

The exercise was performed in my local VirtualBox lab environment.

## 2.1 Environment Setup

**Target:** Metasploitable 2  
**Attacker Machine:** Kali Linux  
**Virtualization Platform:** Oracle VirtualBox  
**Tools Used:** Nmap and Searchsploit

Both virtual machines were configured for laboratory testing.

## 2.2 Host Discovery and Port Scanning

**Objective:**

Identify the target machine and discover its open ports and running services.

**Tool Used:** Nmap

**Activities Performed:**

1. Identified the Metasploitable 2 machine on the lab network.
2. Checked network connectivity between Kali Linux and the target.
3. Performed Nmap scanning to identify open ports.
4. Examined the services running on the discovered ports.
5. Reviewed service versions to identify potentially vulnerable software.

**Command Example:**

```bash
nmap -sV <target-ip>
```

Here, `-sV` enables service version detection.

**Observation:**

The scan identified approximately 23 open ports and several services running on the target machine.

These services provided useful information for further security analysis.

## 2.3 Vulnerability Research Using Searchsploit

**Objective:**

Research publicly known vulnerabilities associated with the services discovered during reconnaissance.

**Tool Used:** Searchsploit

**Activities Performed:**

1. Reviewed the service versions identified through Nmap.
2. Searched for publicly documented exploits related to those services.
3. Identified an entry related to `vsftpd 2.3.4`.
4. Reviewed the associated vulnerability information.

**Command Example:**

```bash
searchsploit vsftpd 2.3.4
```

**Observation:**

Searchsploit identified a known backdoor vulnerability associated with vsftpd version 2.3.4.

This demonstrated how service enumeration can help identify software that may have known security weaknesses.

## 2.4 Results and Findings

| Activity | Finding |
|---|---|
| Target discovery | Metasploitable 2 identified |
| Port scanning | Approximately 23 open ports discovered |
| Service enumeration | Multiple running services identified |
| Vulnerability research | Known vsftpd 2.3.4 backdoor entry found |
| Tools used | Nmap and Searchsploit |

**Result:**

Successfully performed network reconnaissance, identified open ports and services, and researched a known vulnerability associated with one of the discovered services.

**Important Note:** Identifying an exploit through Searchsploit does not mean that the vulnerability was successfully exploited. This exercise focused on reconnaissance and vulnerability research.

# 3. Burp Suite — Web Application Security Testing

## Introduction

Burp Suite is a web application security testing platform used to inspect, intercept, and analyze HTTP and HTTPS traffic between a browser and a web application.

I explored Burp Suite Community Edition to understand how web requests and responses can be examined during security testing.

## 3.1 Burp Suite Setup

**Objective:**

Configure Burp Suite with Firefox in Kali Linux to capture and inspect web traffic.

**Activities Performed:**

1. Started Burp Suite Community Edition.
2. Created a temporary project using the default configuration.
3. Checked the Proxy listener configuration.
4. Confirmed the proxy listener was running on `127.0.0.1:8080`.
5. Configured Firefox to use the Burp proxy.
6. Enabled proxy usage for HTTPS traffic.
7. Opened `http://burp` in Firefox.
8. Downloaded the Burp CA certificate.
9. Imported the certificate into Firefox under Authorities.
10. Enabled trust for the certificate to identify websites.

**Proxy Configuration:**

| Setting | Value |
|---|---|
| Proxy Host | 127.0.0.1 |
| Proxy Port | 8080 |
| Browser | Firefox |
| Proxy Tool | Burp Suite Community Edition |

## 3.2 Understanding Burp Suite Proxy

The Proxy feature allows security testers to intercept and inspect communication between a browser and a web server.

**Concepts Learned:**

- HTTP requests and responses.
- Request headers and parameters.
- Proxy interception.
- HTTP history.
- HTTPS traffic inspection using the Burp CA certificate.

## 3.3 Burp Suite Tools Explored

### Proxy

Used to intercept and inspect HTTP and HTTPS requests and responses.

### HTTP History

Used to review previously captured requests, including their URLs, methods, parameters, and responses.

### Repeater

Used to manually modify and resend requests to observe how the application responds to different inputs.

### Intruder

Used to automate customized request attacks with different payloads. I explored its basic functionality in the Community Edition.
